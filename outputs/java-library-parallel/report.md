## 6 · 操作单元（Normalized Blueprint）

### OP-1 · Base64 整枝（概述 277 + 内嵌类 311 + 方法 821 = 1409 字）保内容迁入「常用类库」
- action：`move | reshape` ｜ status：**NEEDS_DECISION**
- from：知识宇宙 > … > java > 类库 > Base64
- to：知识宇宙 > … > java > 常用类库 > <新语义节点>

| 变体 | 做法 | Δ |
|---|---|---|
| 1a | 原样搬迁（仍为 3 个树节点，父子形态不变） | 树 0（净移动），边 −1（父端改写）+0 |
| 1b | 结构搬迁 + 形态变换：收成 1 个类节点 + 3 tabs（概述 / 内嵌类 / 方法），与 String·Scanner·Files 的 tabs 体系一致 | 树 −2，池 0（同一实体补 tabs 后 2 个子实体可退役） |

**推荐：1b** —— 全库已 tab 化 4 个类（String 33 / Scanner 23 / Files 29 / enum 6）；Base64 以「树子节点」承载方法表是**形态不一致**的孤例。1b 与既有惯例对齐。

### OP-2 · 「类库」总述（719 字，Java 类库维基体正文）归位

### OP-3 · 「类库 > 常用」（2801 字 FQCN 大全清单）留改删

| 变体 | 做法 | Δ |

### OP-4 · 存活节点的 treeId 语义化（现 5 个全部为 tree_<时间戳>_<hash> 形态）
- action：`rename` ｜ status：**NEEDS_DECISION**

| 变体 | 做法 | Δ |
|---|---|---|
| 4a | 只给「本批后仍存活」的节点改名（含 treebind 边 id 两端同步） | 每节点改 1 处 id + 1~2 条边 id |

- 风险：低（映射表驱动，逐条同步边 id）
