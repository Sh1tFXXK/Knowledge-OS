# 2026-07-16 工作日志

## SubsystemStrip 滚动优化
- 用户反馈"多了之后不好翻动"，截图显示底部"规范化理论"卡片被 `max-height: 200px; overflow: hidden` 直接切掉
- 根因：`.subsystem-strip` 用固定 200px + overflow hidden，内部 grid 没有任何滚动容器
- 修复（`src/styles/components.css` + `src/core/SubsystemStrip.tsx`）：
  1. `.subsystem-strip` 改为 `display: flex; flex-direction: column; min-height: 0; max-height: 42vh`，并加过渡动画
  2. `.subsystem-strip-bridge` / `.subsystem-strip-head` 加 `flex-shrink: 0`，头部固定
  3. `.subsystem-strip-grid` 改为 `flex: 1 1 auto; min-height: 0; overflow-y: auto; align-content: start; padding: 2px 8px 4px 0; scrollbar-gutter: stable`
  4. 新增 `.subsystem-strip--expanded` 状态（展开时 `flex: 1 1 auto; max-height: 100%`）
  5. 新增 `.subsystem-strip-toggle` 展开/收起按钮 + `.subsystem-strip-count` 数量徽章
  6. `.subsystem-strip-dim-badge` 去掉 `margin-left: auto`（避免和 toggle 按钮的 `margin-left: auto` 冲突）
- 关键 CSS 经验：flex 子项出滚动条必须给 `min-height: 0` + `overflow-y: auto` + `flex: 1`

## DimensionCanvas 添加新内容自动滚动
- 用户反馈"添加新东西时也看不到"：`handleAddSection` / `handleAddDimension` 只把新内容塞进数组末尾，没有任何滚动逻辑，新加的 section / dim chip / atom 卡片超出视口看不到
- 修复（`src/core/DimensionCanvas.tsx`）：
  1. 加 `dimbarRef` + `rafScroll` 工具函数（双层 RAF 确保 React DOM 已渲染）
  2. `<div className="dc-dimbar" ref={dimbarRef}>` 绑定 ref
  3. dim chip 加 `data-dim-id={dim.id}`，section 加 `data-section-id={section.id}`
  4. `handleAddDimension` 添加后 `scrollIntoView({ behavior: 'smooth', inline: 'end' })` 让 dimbar 横向滚到新 chip
  5. `handleAddSection` 添加后用 `block: 'end'` 让 sections-wrap 滚到新 section 底部
  6. "+ Dimension" / "+ Section" 按钮点击展开输入条时，自动滚到 `.dc-addrow` / `.dc-section-create` 让输入条不被下方内容挤出可见区
- 关键经验：React setState 后 DOM 还没渲染，必须用 `requestAnimationFrame(() => requestAnimationFrame(fn))` 双层 RAF 才能拿到新元素

## DimensionCanvas 编辑框被滚动容器挡住（核心修复）
- 用户反馈"新加内容的话，编辑框会被挡住"：`.dc-section-create`（添加 Section 输入框）、`.dc-group-create`（创建组输入框）、`.dc-dimension-intro`（含 + Section 按钮）原本是 `.dc-sections-wrap` 滚动容器的子元素，用户往下滚浏览 section 时这些编辑框被滚到视口外看不到
- 修复（`src/core/DimensionCanvas.tsx` + `src/styles/components.css`）：
  1. 把 `.dc-dimension-intro` / `.dc-section-create` / `.dc-group-create` 从 `.dc-sections-wrap` 内部移到外部，作为 `.dimension-canvas` 的直接子元素（在 `.dc-control-bar` 之后、`.dc-sections-wrap` 之前）
  2. `.dc-sections-wrap` 内部只保留 OrthogonalMatrixView / SemanticFieldView / DimensionSections / GroupOverlay（GroupOverlay 必须留下，因为它是 `position: absolute` 的覆盖层，坐标基于 `.dc-sections-wrap` 的 scrollLeft/scrollTop）
  3. 用 React Fragment `<>...</>` 包裹 activeDim 分支，让外部 intro + 内部 sections-wrap 都在 `.dimension-canvas` flex column 中
  4. CSS：`.dc-dimension-intro, .dc-section-create, .dc-group-create` 加 `flex-shrink: 0; flex-wrap: wrap`，确保不被 flex 容器压缩
  5. 之前给 "+ Section" 按钮加的 rafScroll scrollIntoView 不再需要（输入框现在脱离滚动容器，自然出现在按钮下方），简化回 `setAddingSection(true)`
  6. 顺手修了 SubsystemStrip.tsx 的 `setExpanded((value) => !value)` 类型错误（`value: boolean` 显式标注）
- 关键布局经验：滚动容器（`overflow-y: auto`）内部的临时编辑框会被滚动条带出视口；如果编辑框需要"始终可见"，必须放到滚动容器外部，作为兄弟元素

## DimensionCanvas 编辑框改成模态框（最终方案）
- 用户反馈"还是不行，你直接放大吧，点击增加点击的时候，它整个会放大"——之前的"移到滚动容器外"方案仍被面板高度挤压，体验差
- 最终方案：把 `addingDim` / `renamingDimId` / `editingCategory` / `addingSection` 四个编辑场景统一改成**模态框**（`position: fixed` 全屏遮罩 + 居中大卡片），完全脱离面板布局
- 修复（`src/core/DimensionCanvas.tsx` + `src/styles/components.css`）：
  1. 四个编辑场景的 JSX 重写为 `.dc-modal-overlay` > `.dc-modal` > `.dc-modal-title` + `.dc-modal-body` + `.dc-modal-actions` 三段结构
  2. 添加 Section 模态框用 `.dc-modal-body--col`（垂直布局放标题输入 + 布局类型 select）
  3. 所有输入框 `autoFocus`，支持 Enter 提交 / Esc 关闭
  4. 点击遮罩关闭（`onClick={() => setXxx(false)}` + 内层 `onClick={e => e.stopPropagation()}`）
  5. CSS：`.dc-modal-overlay` 全屏 `rgba(0,0,0,0.55)` + `backdrop-filter: blur(4px)` + flex center + z-index 1000；`.dc-modal` 宽 `min(480px, 90vw)`，紫色边框 + 多层阴影 + pop-in 动画（`cubic-bezier(0.2, 0.9, 0.3, 1.2)` 弹性进入）
  6. 关键经验：嵌入式编辑框在复杂布局里永远会被某种东西挡住（滚动条 / flex 挤压 / 兄弟元素高度）；模态框用 `position: fixed` 脱离文档流，是唯一可靠的"永远可见"方案
