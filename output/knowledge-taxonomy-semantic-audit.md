# Knowledge OS 知识归属与内容一致性审计

审计日期：2026-08-15

## 结论摘要

- 当前知识树共有 2,268 个树节点、2,161 个被树引用的知识实体。
- “理论门类”共有 33 个领域节点，其中 99 个 MySQL 词条由关键词规则自动归类。
- 对这 99 个词条逐项复核后：49 项归属可接受，18 项只有上下文关联、不适合作为严格父子从属，32 项属于高置信度误归。
- 99 个词条全部从 MySQL 功能目录中被移除，只保留理论目录位置；因此错误归类不仅增加了错误入口，还让复制、安全、备份等 MySQL 功能目录出现空壳。
- MySQL 词汇表 R 段存在连续 6 个词条的正文串位。
- 树中另有 163 个被引用实体没有正文；其中不少是结构容器，但也包含应补全的真实知识节点。
- 本报告只审计，不修改、移动或删除现有数据。

## 内容串位

MySQL 词汇表整理版的 R 段发生连续错位，当前实体中的正文关系如下：

| 实体 | 当前正文实际属于 |
| --- | --- |
| relational | relevance |
| relevance | REPEATABLE READ |
| REPEATABLE READ | repertoire |
| repertoire | replica |
| replica | replication |
| replication | 只剩 replication 定义尾部 |

原始 MySQL 词汇表中的 REPEATABLE READ 正文仍然存在，说明这是整理器标题识别错位，不是原始资料错误。

## MySQL 功能目录问题

- 99 个理论词条在 MySQL 功能目录中的保留数为 0；当前实现将它们全部搬走，而不是增加共享引用。
- “复制与高可用”和“安全、账号与认证”成为空目录；“备份、运维与诊断”只剩一个笼统容器。
- `.MYD` 与 `.MYI` 是 MyISAM 文件，却位于 `InnoDB 内部结构 > 数据文件`。
- InnoDB Page 下存在多组同义或近义节点：`Page Directory / 数据目录部分`、`Free Space / 空间部分`、`User Records / 行记录 / 记录部分`。
- `Undo页`、`事务数据页`等节点有名称但没有解释，无法判断其精确指称。

## 其他全局异常

- `编程语言 > go > undefined`：导入根标题丢失，实体标签和标题都是 `undefined`。
- `程序语言理论 > Python`：正文仍是“目录引用的占位知识实体”。
- 163 个被树引用的实体没有正文。大量为空容器，但也包含类加载、JVM、并发、Spring 等可独立知识节点。
- 已有数据整理规则会移除错误的 `编译原理 > NoSQL`，但理论目录生成器会再次创建它；当前干跑仍报告 1 个待移除树项。

## 根因

1. 分类只读取节点 ID、标签、标题和英文词条，不读取定义正文。
2. 所有候选词条被强制分到一个且仅一个理论领域。
3. 没有匹配时仍使用 `dimensions` 回退到编译原理、存储系统或操作系统。
4. `cluster`、`merge`、`query`、`database`、`table` 等宽泛子串直接决定学科归属。
5. 归入理论目录后，原 MySQL 功能目录位置被删除。
6. 三套 MySQL 分类脚本各自维护不同的正则表和优先级，规则会互相覆盖。
7. 测试只验证目录数量、唯一 ID 和引用完整，不验证语义归属。
8. 已知问题依赖事后整理；重新生成目录会把错误重新引入。

## 保守修复顺序

1. 先修复 R 段 6 个正文串位，保留原始卡片与来源信息。
2. 停止从 MySQL 功能目录移除理论词条，改为同一 `nodeRef` 的多位置引用。
3. 用显式、可审查的归属表替换理论门类正则；未确认项进入“待审核”，不使用默认学科回退。
4. 移走 32 个高置信误归项，将 18 个弱关联项改成 reference/classification 关系。
5. 补齐关系代数、规范化、复杂性等领域的正式核心知识；不要用 MySQL 术语数量冒充学科内容。
6. 合并三套互相冲突的分类入口，并增加负向语义测试，例如“clustered index 不得属于 distributed systems”。
7. 最后处理 `undefined`、占位定义和无正文节点；这些操作与语义搬迁分批执行，便于回滚。
