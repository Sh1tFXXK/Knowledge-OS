# Redis 底层数据结构总览

Redis 没有直接使用 C 语言的传统数据结构，而是自己构建了一套底层数据结构，并在其上构建了字符串、列表、哈希、集合、有序集合五种对象。本节点汇总《Redis设计与实现》第一部分（第 2~8 章）的内容框架，各章正文见对应章节节点。

## 六种底层数据结构

- **SDS（简单动态字符串，第 2 章）**：Redis 的默认字符串表示。结构含 `len`（已用长度）、`free`（未使用长度）、`buf[]`（字节数组）。相比 C 字符串：O(1) 取长度、杜绝缓冲区溢出、减少修改时的内存重分配（空间预分配 + 惰性空间释放）、二进制安全、兼容部分 C 字符串函数。
- **链表（第 3 章）**：双端无环链表，`listNode` 含 prev/next 指针，`list` 结构含表头/表尾指针、长度及 dup/free/match 类型特定函数。被列表键、发布与订阅、慢查询、监视器等使用。
- **字典（第 4 章）**：基于哈希表（MurmurHash2 算法，`ht[2]` 双表结构），采用链地址法解决哈希冲突，通过渐进式 rehash 完成扩容/缩容（rehashidx 分多次迁移，避免阻塞）。是哈希键与 Redis 数据库本身的底层实现。
- **跳跃表（第 5 章）**：有序数据结构，`zskiplistNode` 含后退指针与多层前进指针（层高幂次随机 1~32），平均 O(logN) 查找。用于有序集合键及集群节点内部结构。
- **整数集合（第 6 章）**：`intset` 保存不重复整数值的有序数组，支持 int16/int32/int64 升级（只升不降），是集合键的底层实现之一。
- **压缩列表（第 7 章）**：为节约内存设计的顺序型结构，连续内存块，节点含 previous_entry_length 与 encoding/content。是列表键和哈希键元素较少时的底层实现；注意连锁更新问题。

## 对象系统（第 8 章）

- Redis 在上述数据结构之上构建了对象：`redisObject` 含 type、encoding、lru（空转时长）、refcount（引用计数）、ptr。
- 五种对象：字符串、列表、哈希、集合、有序集合；每种对象可在不同编码间转换（如列表的 ziplist↔linkedlist，哈希的 ziplist↔hashtable，集合的 intset↔hashtable，有序集合的 ziplist↔skiplist）。
- 对象共享：整数值 0~9999 的字符串对象被共享以节约内存。
- 类型检查基于 type；命令多态基于 encoding。
